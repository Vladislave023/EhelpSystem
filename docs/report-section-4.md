# Раздел 4. Реализация и тестирование

## 4.1. Стек технологий

Текущая реализация проекта опирается на следующие технологии:

- `Python 3.11+` — основной язык реализации backend, UI и ML-пайплайна;
- `PySide6` — настольный интерфейс приложения;
- собственная база знаний в `JSON` — хранение признаков, диагнозов, лечения и протоколов помощи;
- `scikit-learn` — обучение модели классификации;
- `joblib` — сохранение обученной модели;
- `unittest` — модульные тесты backend.

Подход к реализации комбинированный:

- знания предметной области задаются явно через базу знаний;
- на основе этих знаний автоматически генерируется обучающая выборка;
- модель машинного обучения обучается классифицировать состояние по тем же признакам.

## 4.2. Модель классификации

### Выбор источника данных

После проверки публичных источников наиболее практичным вариантом для проекта оказалась **синтетическая табличная выборка**, автоматически сгенерированная на основе базы знаний проекта.

Причина выбора:

- доступные публичные датасеты по теме ран и ожогов в основном являются **изображениями**, а не табличными признаками;
- часть медицинских наборов данных доступна **только по запросу** или покрывает лишь узкие случаи;
- для нашей системы нужна именно **структурированная выборка по симптомам**, совпадающая с признаками базы знаний.

### Проверенные варианты публичных датасетов

1. `wound_dataset` на Kaggle
   - содержит изображения ран;
   - не подходит как табличная выборка по признакам;
   - ссылка: [Kaggle wound_dataset](https://www.kaggle.com/datasets/yasinpratomo/wound-dataset/data)

2. `Burn Research Dataset` от American Burn Association
   - содержит burn-specific data, доступ предоставляется по запросу;
   - охватывает ожоги, но не всю нашу предметную область;
   - ссылка: [American Burn Association Research Dataset](https://www.ameriburn.org/burn-care-team/research/research-dataset)

3. `injury-severity-degree` на Hugging Face
   - это текстовый датасет по описаниям производственных инцидентов;
   - не совпадает с нашей постановкой задачи по симптомам бытовых травм;
   - ссылка: [Hugging Face injury-severity-degree](https://huggingface.co/datasets/uisikdag/injury-severity-degree)

### 4.2.1. Описание выборки для обучения

В проекте используется автоматически сгенерированная выборка.

Источником данных выступает текущая база знаний проекта:

- признаки;
- допустимые значения признаков;
- нормальные значения;
- диагнозы;
- значения признаков для каждого диагноза.

Сценарий генерации:

- для каждого диагноза генерируется одинаковое число объектов;
- значения значимых признаков выбираются случайно из диапазонов, закрепленных за диагнозом;
- значения остальных признаков выбираются из нормальных диапазонов;
- итоговая таблица сохраняется в CSV.

Характеристики выборки определяются автоматически при запуске скрипта `train_model.py`.

На текущей конфигурации базы знаний:

- количество признаков: `9`;
- количество классов: `7`;
- классы: `здоров`, `поверхностный порез`, `глубокий порез`, `ожог I степени`, `ожог II степени`, `ушиб`, `заноза`;
- размер выборки зависит от параметра `samples_per_class`.

По умолчанию генератор создает:

- `250` объектов на каждый класс;
- всего `1750` объектов.

Используемые признаки:

- `Глубина повреждения` — вещественный признак;
- `Площадь повреждения` — вещественный признак;
- `Наличие кровотечения` — бинарный целочисленный признак;
- `Интенсивность боли` — целочисленный признак;
- `Покраснение кожи` — бинарный целочисленный признак;
- `Наличие волдырей` — бинарный целочисленный признак;
- `Отёк` — бинарный целочисленный признак;
- `Наличие гематомы` — бинарный целочисленный признак;
- `Наличие инородного тела` — бинарный целочисленный признак.

### 4.2.2. Описание метода обучения

В качестве метода классификации используется `RandomForestClassifier`.

Причины выбора метода:

- хорошо работает на табличных данных смешанного типа;
- устойчив к небольшому шуму;
- не требует сложной нормализации признаков;
- подходит для задач с нелинейными разделяющими правилами.

Базовые параметры модели:

- `n_estimators = 200`
- `max_depth = 8`
- `min_samples_split = 4`
- `min_samples_leaf = 2`
- `random_state = 42`

Разбиение выборки:

- `80%` — обучающая часть;
- `20%` — контрольная проверка;
- используется `stratify`, чтобы сохранить баланс классов.

После запуска `train_model.py` автоматически формируются:

- CSV-файл датасета;
- обученная модель `.joblib`;
- `metrics.json`;
- `classification_report.txt`;
- `confusion_matrix.csv`.

## 4.3. Тестирование

Тестирование можно описывать в трех частях:

1. Модульные тесты backend
   - проверка диагностики;
   - проверка корректности базы знаний;
   - проверка CRUD-операций редактора знаний.

2. Тестирование через интерфейс
   - загрузка признаков;
   - добавление и удаление признака;
   - проверка валидации диапазонов;
   - дальнейшая проверка экранов диагнозов, лечения и протоколов.

3. Тестирование модели
   - запуск `train_model.py`;
   - анализ `accuracy`;
   - анализ матрицы ошибок;
   - проверка того, что классы корректно различаются по признакам.

```powershell
python train_model.py
```
