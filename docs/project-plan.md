# План и структура будущей программы

## 1. Цель программы

Разработать настольную систему по теме курсовой: диагностика распространенных бытовых травм и выдача рекомендаций по первой помощи на основе базы знаний.

Программа должна повторять логику, описанную в курсовой, и визуально опираться на скрины из документа:

- слева постоянная навигация по разделам;
- справа рабочая область текущего модуля;
- табличные формы для редактирования знаний;
- отдельный экран ввода признаков состояния пациента;
- отдельный экран результата с диагнозом и протоколом помощи.

## 2. Основные модули системы

### 2.1. Редактор знаний

Нужен для наполнения и изменения базы знаний.

Подмодули:

- `Признаки`
  - название признака;
  - допустимые значения;
  - нормальные значения.
- `Диагнозы`
  - название диагноза;
  - признаки диагноза;
  - допустимые значения признаков для диагноза;
  - назначенное лечение.
- `Действия`
  - список элементарных действий первой помощи.
- `Протоколы помощи`
  - выбор лечения;
  - список действий, входящих в протокол.
- `Названия лечения`
  - название лечения;
  - описание лечения.

### 2.2. Система ввода данных пациента

Нужна для ввода текущего состояния пострадавшего.

Функции:

- показать список признаков;
- дать ввести значение каждого признака;
- проверить, что значения принадлежат допустимым диапазонам;
- сохранить введенное состояние пациента для решения задачи.

### 2.3. Решатель задач

Нужен для определения диагноза и выбора протокола помощи.

Логика из курсовой:

1. Проверить корректность входных данных.
2. Проверить состояние `здоров`.
3. Последовательно перебрать диагнозы.
4. Найти первый диагноз, для которого выполнены условия.
5. Определить лечение.
6. Построить протокол помощи.
7. Сформировать объяснение результата.

### 2.4. Экран результата

Нужен для вывода:

- диагноза пациента;
- основания выбора;
- названия лечения;
- списка действий первой помощи.

## 3. Роли пользователя

### 3.1. Эксперт

Работает с редактором знаний:

- добавляет и редактирует признаки;
- добавляет и редактирует диагнозы;
- назначает лечение диагнозам;
- собирает протоколы помощи;
- проверяет полноту базы знаний.

### 3.2. Пользователь

Работает с пациентом:

- вводит признаки состояния;
- запускает определение диагноза;
- получает рекомендации по первой помощи.

## 4. Сущности предметной области

### 4.1. База знаний

- `Feature` — признак;
- `Diagnosis` — диагноз;
- `DiagnosisFeatureRule` — правило признака для диагноза;
- `Treatment` — название лечения;
- `ActionItem` — действие первой помощи;
- `Protocol` — протокол помощи;
- `ProtocolAction` — связь протокола и действия.

### 4.2. Данные пациента

- `PatientState` — набор значений признаков пациента;
- `PatientFeatureValue` — одно значение признака;
- `DecisionResult` — результат решения:
  - диагноз;
  - лечение;
  - действия;
  - объяснение.

## 5. Предлагаемая логическая архитектура

### 5.1. Слои

- `UI`
  - окна, страницы, формы, таблицы, кнопки.
- `Application`
  - сценарии работы: добавить диагноз, сохранить протокол, определить диагноз.
- `Domain`
  - сущности и бизнес-правила.
- `Infrastructure`
  - хранение данных, загрузка/сохранение, локальная база.

### 5.2. Поток данных

`UI -> Application -> Domain -> Storage`

`Storage -> Application -> UI`

## 6. Структура экранов

### 6.1. Основная оболочка

- левое меню;
- заголовок текущего раздела;
- центральная рабочая область;
- кнопки добавления, удаления, выбора, подтверждения.

### 6.2. Экран "Признаки"

- таблица:
  - название признака;
  - допустимые значения;
  - нормальные значения;
- форма добавления новой записи;
- удаление записи.

### 6.3. Экран "Диагнозы"

- список диагнозов;
- таблица признаков выбранного диагноза;
- значения признаков для диагноза;
- выпадающий список лечения;
- форма добавления диагноза.

### 6.4. Экран "Действия"

- список действий;
- форма добавления действия;
- удаление действия.

### 6.5. Экран "Протоколы помощи"

- выбор лечения;
- список действий, входящих в протокол;
- добавление действия в протокол;
- удаление действия из протокола.

### 6.6. Экран "Названия лечения"

- таблица:
  - название лечения;
  - описание;
- форма добавления;
- удаление.

### 6.7. Экран "Пациент"

- список признаков состояния;
- поля ввода значений;
- кнопка `Готово` / `Определить`.

### 6.8. Экран "Результат"

- найденный диагноз;
- текст объяснения;
- рекомендованное лечение;
- пошаговый протокол помощи.

## 8. Минимальный MVP

Первую рабочую версию лучше делать в таком порядке:

1. Каркас приложения и левое меню.
2. Экран `Признаки`.
3. Экран `Названия лечения`.
4. Экран `Действия`.
5. Экран `Диагнозы`.
6. Экран `Протоколы помощи`.
7. Экран `Пациент`.
8. Решатель задач.
9. Экран результата.
10. Проверки корректности и доработка интерфейса под скрины.

## 9. Что важно сохранить из курсовой

- Разделение на редактор знаний и пользовательский режим.
- Логику вывода: признаки -> диагноз -> лечение -> протокол.
- Табличный стиль экранов, как на макетах.
- Простую и понятную навигацию без перегруженного интерфейса.
- Локальное хранение базы знаний, чтобы программа могла работать автономно.

## 10. Рекомендуемое следующее действие

Следующим шагом можно сделать один из двух вариантов:

1. Утвердить стек разработки и сразу создать каркас проекта.
2. Сначала детально описать каждое окно и все поля ввода по образцу скринов.

Для старта разработки оптимально идти от каркаса экранов, а затем подключать бизнес-логику решателя.
