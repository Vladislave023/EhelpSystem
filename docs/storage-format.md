# Формат хранения базы знаний

## Текущий формат

Для курсовой версии проекта база знаний хранится в JSON-файле:

[sample_knowledge_base.json](C:\Users\Mvide\Desktop\Диплом+ лаба ИЛ\EhelpS\data\sample_knowledge_base.json)

Этот формат выбран как основной на первом этапе, потому что он:

- простой для отладки;
- легко читается вручную;
- не требует установки СУБД;
- хорошо подходит для демонстрации логики редактора знаний.

## Структура JSON

Файл состоит из пяти основных разделов:

- `features`
  - список признаков;
  - каждый признак содержит:
    - `name`
    - `allowed_values`
    - `normal_values`
- `actions`
  - список элементарных действий первой помощи.
- `treatments`
  - список названий лечения;
  - каждый элемент содержит:
    - `name`
    - `description`
- `diagnoses`
  - список диагнозов;
  - каждый диагноз содержит:
    - `name`
    - `feature_ranges`
    - `treatment_name`
- `protocols`
  - список протоколов;
  - каждый элемент содержит:
    - `treatment_name`
    - `actions`

## Принципы целостности

При сохранении редактор знаний должен обеспечивать:

- уникальность названий признаков;
- уникальность названий диагнозов;
- уникальность названий лечения;
- существование признаков, на которые ссылаются диагнозы;
- существование лечения, назначенного диагнозу;
- существование протокола для лечения, назначенного не-нулевому диагнозу;
- существование действий, входящих в протокол;
- запрет удаления сущностей, если на них есть ссылки.

## Формат диапазонов значений

Для значений признаков используется строковое представление диапазонов:

- `I[a;b]` — целочисленный диапазон;
- `R[a;b]` — вещественный диапазон.

Примеры:

- `I[0;1]`
- `I[3;10]`
- `R[0;5]`
- `R[0.1;10]`

## Дальнейшее развитие

Позже этот же слой можно будет перевести на SQLite без изменения бизнес-логики:

- доменная модель останется прежней;
- сервисы `DiagnosisService` и `KnowledgeBaseEditorService` останутся прежними;
- изменится только инфраструктурный слой хранения.
